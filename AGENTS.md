# AGENTS.md — Instructions for AI Coding Agents

This file provides instructions for IBM Bob and other AI coding agents working on the **NyayaTrace / NyayaSetu** repository. Read this file before making any changes.

---

## Project Overview

NyayaTrace (package name: `nyayasetu`) is a **local, offline-first legal case management workspace** for Indian advocates and legal clerks. It runs entirely on a developer's machine — no cloud backend, no hosted database.

Key capabilities:
- Create and manage legal cases (criminal, civil, bail, parole)
- Upload court documents (PDF and images); extract text via PDF.js and Tesseract.js OCR
- Run local or AI-assisted (Gemini / OpenAI / Groq / OpenRouter / Ollama) case analysis
- Track hearings, orders, bail conditions, and statutory bail deadlines
- Review discrepancy findings linked to source document pages
- Browse an IPC ↔ BNS section concordance with curated landmark judgments
- Generate bail briefs and case reports (screen and DOCX)

## Coding Conventions

- **TypeScript everywhere.** All files use `.ts` / `.tsx`. Do not introduce `.js` files.
- **Tailwind CSS only.** Do not add custom CSS files unless absolutely necessary. Use `cn()` from `lib/utils.ts` for conditional classes.
- **shadcn/ui components.** Reuse existing primitives from `components/ui/`. Do not install new UI libraries without discussion.
- **Drizzle ORM for all DB access.** Never write raw SQL strings unless the pattern is already established (e.g., the FTS5 query in `app/api/search/route.ts`).
- **Server/client separation.** All API routes must include `export const runtime = 'nodejs'`. Do not import server-side modules (`better-sqlite3`, `fs`, `bcryptjs`, `tesseract.js`) in client components.
- **Import alias.** Use `@/` to reference `lib/`, `components/`, `app/` etc. Do not use relative paths that traverse more than one directory level.
- **Error handling.** API routes must return structured `{ error: string }` JSON with an appropriate HTTP status. Never expose internal stack traces in responses.
- **Naming.** File names use `camelCase.ts` for utilities, `PascalCase.tsx` for components. Route files are always `route.ts`. Page files are always `page.tsx`.

## Making Changes Safely

1. **Never modify `lib/db/schema.ts` without creating a matching migration.** Run `npm run db:generate` after schema changes, then `npm run db:migrate` to apply them. Migration files in `drizzle/` must be committed.
2. **AI analysis providers are symmetric.** All provider files in `lib/analysis/` follow the same signature: `generate*Analysis(documents, language) → Promise<AIAnalysis>`. Keep them consistent.
3. **Legal data is static and curated.** `lib/legal/sections.ts` and `lib/legal/landmarkJudgments.ts` contain hand-verified data. Do not auto-generate or fabricate entries. All judgment entries must have verifiable citations; use `verificationNote` when uncertain.
4. **OCR pipeline changes need end-to-end testing.** Changes to `lib/ocr/index.ts` affect text extraction for every case. Test with a real multi-page scanned PDF before committing.
5. **Do not break the auth dual-layer.** `lib/auth.ts` (client localStorage) and `lib/auth-server.ts` (DB sessions) coexist. The middleware in `middleware.ts` guards routes using the `nyayasetu_session` cookie (server-side). Client components use `lib/auth.ts` for UI state. Both layers must remain consistent.
6. **File upload validation is multi-layered.** `app/api/documents/route.ts` validates file size (≤ 20 MB), extension, MIME magic bytes, and duplicate SHA-256 hash. Do not weaken these checks.
7. **Backward compatibility.** The SQLite database file (`nyayatrace.db`) persists locally. Every schema change must be additive or include a safe migration. Never drop columns without a migration.

## Reusing Existing Components and Services

- **Query helpers in `lib/queries/`.** Use `getCaseById`, `getDocumentWithPages`, `getFindingWithSources`, `getDashboardStats` etc. before writing new queries.
- **Auth utilities.** Use `getRequiredSession(request)` from `lib/auth-server.ts` in any API route that needs authentication. It throws `AuthError` on failure — catch it and return 401.
- **OCR pipeline.** Always call `processDocument(filePath, language)` from `lib/ocr/index.ts`. Do not write new OCR logic inline in route handlers.
- **Legal section detection.** Use `extractSections` from `lib/analysis/sectionExtractor.ts` and `LEGAL_SECTIONS_DB` from `lib/legal/sections.ts`.
- **Statutory bail calculation.** Use `calculateStatutoryBail(caseData)` from `lib/analysis/statutoryBail.ts`.
- **Toast notifications.** Use `sonner`'s `toast` function. Do not add other notification libraries.
- **Shared UI.** Use `components/shared/LoadingSkeleton.tsx` and `components/shared/CitationHoverCard.tsx` where applicable.

## Testing, Linting, Building, and Validation

There is **no automated test suite** in this repository. All validation is manual or via build checks.

```bash
# Lint (ESLint with Next.js rules)
npm run lint

# Type-check (TypeScript — no emitting)
npx tsc --noEmit

# Development server (Turbopack)
npm run dev

# Production build
npm run build

# Database: apply pending migrations
npm run db:migrate

# Database: generate migration from schema changes
npm run db:generate

# Database: push schema without migration file (dev only)
npm run db:push
```

**Before committing any change:**
1. Run `npm run lint` — fix all errors.
2. Run `npx tsc --noEmit` — fix all type errors.
3. Run `npm run build` to confirm the production build passes.
4. Verify the affected feature manually in the dev server.

## Security Requirements and Environment Variables

- **Never commit real API keys.** All keys live in `.env.local` (gitignored). `.env.example` contains safe placeholder values and comments.
- **Never log API keys or session tokens.** Server logs may print to the terminal but must not contain credentials.
- **Never put secrets in `lib/auth.ts`.** That file runs in the browser. Real password hashing happens in `lib/auth-server.ts` (server only).
- **The `uploads/` directory is gitignored.** Never commit uploaded case documents.
- **The `nyayatrace.db` file is checked in for development seeding.** It must never contain real case data or real personal information.
- **Environment variable access is server-only.** Only API routes and server components may read `process.env.*`. Client components must not import server-side env vars.

### Required environment variables (optional AI features)

| Variable | Provider | Default model |
|---|---|---|
| `GEMINI_API_KEY` or `GOOGLE_API_KEY` | Google Gemini | `gemini-2.0-flash` |
| `OPENAI_API_KEY` | OpenAI | `gpt-4o-mini` |
| `GROQ_API_KEY` | Groq | `llama-3.3-70b-versatile` |
| `OPENROUTER_API_KEY` | OpenRouter | `openai/gpt-4o-mini` |
| `OLLAMA_BASE_URL` + `OLLAMA_MODEL` | Ollama (local) | `llama3` |

None of these are required to run the application. All AI features degrade gracefully when keys are absent.

## Rules for Maintaining Existing Functionality

- **Do not redesign UI components** unless explicitly requested. Change only what is necessary for the task.
- **Do not rename or remove existing API route paths.** The frontend depends on specific route shapes. Any change to route signatures must be reflected in all callers.
- **Do not change the SQLite database filename.** It is `nyayatrace.db` (as configured in `drizzle.config.ts` and referenced in `app/api/search/route.ts`).
- **Do not alter the session cookie name** (`nyayasetu_session`). It is referenced in `middleware.ts`, `lib/auth-server.ts`, and API routes.
- **Do not remove or reorder seed scripts.** Scripts in `lib/db/` are allowlisted in `package.json` and may be used for demos.
- **Do not add new `devDependencies` to `dependencies` or vice versa.** Keep the separation clean.
- **Do not add `use client` to files that are currently server components**, and do not remove it from files that require client-side features.

---

## Avoiding Common Mistakes

- **Do not fabricate legal data.** `lib/legal/landmarkJudgments.ts` contains a strict accuracy policy in its file header. Do not add judgment entries without verified citations.
- **Do not add placeholder routes or stub endpoints.** Every API route must be fully functional.
- **Do not duplicate query logic.** Always check `lib/queries/` before writing new Drizzle queries.
- **Do not install unnecessary dependencies.** The project already includes Framer Motion, Recharts, `lucide-react`, and `date-fns`. Use them.
- **Do not add unrelated refactoring.** Make the minimal change that solves the task.
